# Concept Explainer narration structure

Use this topic-aware causal arc for Concept Explainer lessons. It is a teaching structure, not a requirement to create six title cards.

1. **What is the topic?** Define it in plain language and anchor it with a concrete situation or analogy.
2. **What is the current problem?** Explain the limitation, pain point, failure, or unanswered question that makes the topic relevant.
3. **What does it solve?** State the specific outcome and benefits, while being honest about what it does not solve.
4. **How does it solve the problem?** Explain the mechanism causally in small steps; connect components to the problem they address.
5. **Implementation / worked example.** Use one coherent end-to-end example. For programming, use valid code, explain key lines, and state expected output. For non-code topics, use a practical worked example.
6. **Conclusion.** Recap the problem-to-solution chain, when to use the idea, one limitation or common mistake, and a memorable takeaway.

## Quality gates

- Open directly with the topic or central problem; avoid generic greetings and filler.
- Each sentence must add a new explanation, causal step, or advance the worked example.
- Use one consistent example throughout when possible.
- Never just read code aloud: explain what the key operations do and what result to expect.
- Keep claims proportional; mention relevant limitations and trade-offs.
- Adapt the structure to the domain. For algorithms, trace inputs and outputs; for system design, cover requirements, bottlenecks, architecture and trade-offs; for tools, explain the pain point, mechanism, implementation and limits.
- Visuals should illustrate the exact narration sentence. Do not use generic animation unrelated to the spoken explanation.
- End with a concise recap and a memorable takeaway. A subscription CTA is only appropriate for social-video destinations.
