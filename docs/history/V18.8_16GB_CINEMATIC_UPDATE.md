# v18.8 — 16GB Cinematic Generation Update

## What changed

- QUALITY is now the default new-story profile.
- Added native Qwen Image 2.1 INT8 ComfyUI workflow for the 16GB image path.
- Qwen generates at 576x1024, then applies RealESRGAN x2 and finishes at 864x1536.
- Disabled the optional Qwen prompt-enhancer model in the 16GB path to avoid another large text-encoder allocation.
- Expanded Qwen scene-prompt budgets for richer environment, material, lighting and continuity descriptions.
- Character-reference scenes stay on SDXL + IPAdapter using a dedicated SDXL checkpoint instead of silently ignoring the reference image.
- Wan 2.2 local video defaults are now 480x832, 16 fps, 16 steps and 6 seconds maximum for a 16GB target.
- MiniMax H3 remains a native ComfyUI option, but has a separate 24GB VRAM fail-fast guard. It is not treated as a MiniMax API workflow.
- Standalone Video Generation now maps MiniMax H3 to the native local H3 graph and uses the app's standard Voice Lab/TTS narration path rather than H3 as the voice generator.
- The GPU startup script can download the Qwen INT8 image models and RealESRGAN x2 model into the persistent ComfyUI volume.
- Chatterbox is set to CPU in the supplied 16GB `.env` to avoid competing for the same GPU memory as Qwen/Wan. Voice quality is unchanged; generation may be slower.

## Hardware target

This release is tuned for a **16GB NVIDIA GPU**. It is not a promise that every workflow fits every 16GB card; driver, architecture, ComfyUI version, custom nodes and concurrent GPU processes affect actual peak VRAM.

Qwen Image 2.1 is deliberately kept at 576x1024 for the diffusion pass. Current ComfyUI documentation provides an INT8 Qwen Image 2.1 workflow, and a current 16GB deployment report measured roughly 15.8GB peak at 1024x1024, which is why this application keeps additional headroom and does not enable the optional prompt-enhancer model.
